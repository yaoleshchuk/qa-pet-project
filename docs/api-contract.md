# Учебный API-контракт mock-сервера

Дата фиксации: 2026-09-23. Машиночитаемое описание: [api-contract.yaml](api-contract.yaml).

Контракт описывает только локальный учебный mock и не имитирует полный Booking.com API.
Все ответы, кроме `204 No Content`, используют JSON. Ошибка имеет единый вид
`{"error":{"code":"...","message":"..."}}`.

## Правила статусов

- `400 Bad Request`: запрос нельзя корректно интерпретировать — malformed JSON,
  неверный тип или отсутствующее обязательное поле, неизвестное поле review, неверный
  синтаксис положительного integer ID, даты не в строгом `YYYY-MM-DD`, только одна из
  двух дат, нечисловая/отрицательная цена, повторённый query parameter, неподдерживаемая
  валюта.
- `401 Unauthorized`: пара email/password не совпала с тестовыми credentials.
- `404 Not Found`: отель не существует; отзыв не существует либо не принадлежит отелю
  из URL; маршрут не существует. Для чужого отзыва используется тот же `404`, что и для
  отсутствующего.
- `422 Unprocessable Entity`: структура корректна, но значение нарушает правило —
  rating вне `1..5`, comment после trim имеет длину вне `1..500` Unicode code points,
  `checkout <= checkin`, `min_price > max_price`.

## Reviews

`POST /api/hotel/{hotelId}/reviews` требует оба поля: integer `rating` и string
`comment`. `PUT /api/hotel/{hotelId}/reviews/{reviewId}` — частичное обновление, но
требует хотя бы одно из них. Для обоих методов действуют одинаковые value-правила;
лишние поля отклоняются. Comment сохраняется после trim. Сервер сначала проверяет
отель и принадлежность review, затем тело обновления. Отклонённый `PUT` не меняет
ресурс.

Успешный `DELETE` отвечает `204`. Повторный `DELETE` того же URL отвечает `404
REVIEW_NOT_FOUND`.

## Поиск, даты и доступность

`checkin` и `checkout` передаются только вместе. Это реальные календарные даты в
строгом формате `YYYY-MM-DD`; ограничение относительно текущей даты намеренно не
вводится, чтобы fixture оставался детерминированным. Stay — полуоткрытый интервал
`[checkin, checkout)`. Отель исключается, если он пересекает один из фиксированных
занятых интервалов:

- hotel `2`: `[2026-07-01, 2026-07-05)`;
- hotel `4`: `[2026-08-10, 2026-08-15)`.

Поэтому checkout в день начала следующего интервала не считается пересечением.

## Валюта и фильтрация цены

Seed price хранится в EUR. Фиксированные тестовые курсы: `EUR=1`, `USD=1.10`,
`GBP=0.85`. Поле `price` пересчитывается и округляется до двух десятичных знаков;
ответ также содержит `currency` и `currency_symbol`. `min_price`/`max_price`
применяются к уже пересчитанной цене в запрошенной валюте. Валюта по умолчанию — EUR.

## Восстановление fixture

`POST /api/test/reset` — test-only endpoint, возвращающий `204`. Он восстанавливает
три seed review, очищает wishlist и возвращает следующий создаваемый review ID к
`100`. Перезапуск процесса приводит к тому же состоянию. Endpoint не предназначен
для production API.

Wishlist оставлен в прежней учебной модели и не расширяется правилами review CRUD;
его усиление относится к последующим согласованным работам, а не к этому контракту.
